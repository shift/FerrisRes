# Getting the missing datasets into the builder's format

Status: **plan, 2026-11-26.** The target is one thing only: UTF-8 text files in a
directory tree, with a licence per source, so `ferrisres corpus build` can read
them through its `local` source adapter. Everything below is a way to produce
that from a source that ships in a different shape.

## The rule that shapes every route

**Convert outside the engine.** The builder takes text; the sources ship as
parquet, jsonl or archives. Adding `parquet`/`arrow` to the engine for a one-off
conversion buys binary size and dependencies forever. Conversion belongs in a
Kaggle notebook (`pyarrow` and `datasets` are preinstalled), whose output is a
Kaggle dataset of plain `.txt` shards. The engine then sees only text and a
licence.

```
HF parquet --(Kaggle notebook: stream, filter, sample)--> *.txt shards
           --(Kaggle dataset)--> builder `local` source --> corpus
```

## What each missing source needs

| source | HF id | licence | how to get text | target |
|---|---|---|---|---|
| English web | `HuggingFaceFW/fineweb-edu` (`sample-10BT`) | ODC-By | stream parquet, take the `text` column, stop at the budget | ~175M tok |
| German web | `HuggingFaceFW/fineweb-2` config `deu` | ODC-By | same | ~50M tok |
| Code | `bigcode/the-stack-dedup`, licence-filtered | per-file, filter to MIT/Apache/BSD | select where the file licence is permissive; keep `content` | ~100M tok |
| Instruction SFT | `HuggingFaceTB/smoltalk` | Apache-2.0 | render each conversation through our chat template into jsonl, then text | ~75M tok |
| Tool use | **generate** from our own tool schemas | ours (CC0) | teacher calls our tools against a sandbox; see `tasks/synthetic-tool-traces.md` | ~60M tok |
| Math / reasoning | `AI-MO/NuminaMath-CoT` | Apache-2.0 | `problem` + `solution` as text | ~25M tok |
| Long documents | Project Gutenberg, more titles | public domain | already have the adapter; fetch a larger slice | ~15M tok |
| Soul / persona | **authored + generated** | ours (CC0) | 30 authored souls + 500 synthetic × 5–10 tasks, answered by the teacher | ~5M tok |
| Evals | held-out per source + `eval-unseen-souls` | ours | never trained on; hash and exclude | 200–1,000 items |

**Licence verification is a gate, not a note.** Each row's card must be read at a
pinned revision before the fetch, and the revision recorded in the plan. Two rows
in the current index are deliberately excluded from the release corpus and stay
in the private one: Dolly (CC-BY-SA) and xLAM (NC).

## The one piece of code that unblocks half of it

`tools/` has no parquet reader, so FineWeb-Edu and FineWeb-2 cannot be fetched at
all today. One Kaggle notebook fixes that:

1. `datasets.load_dataset(id, split, streaming=True)`;
2. take `text` (FineWeb) or `problem`/`solution` (NuminaMath), filter length and
   language heuristics, dedupe by a hash of the first 200 characters;
3. write `part-NNNNN.txt` of ~100 MB each and a `manifest.json` with rows,
   bytes, dataset id, revision and licence;
4. record the row count and stop at the budget — streaming means we never
   download 10B tokens to use 175M.

The engine then needs nothing new: `sources: [{ "id": "web-en", "path":
"/data/web-en", "licence": "ODC-By", "revision": "<sha>" }]`.

## Order

1. **parquet extractor → FineWeb-Edu + FineWeb-2** (225M tokens, 45% of the mix);
2. corpus rebuild at the new volume, with the 32k tokenizer, and the
   reproducibility and held-out gates;
3. SFT and math (100M combined) — the categories that make it a *chat* model
   rather than a next-token model;
4. tool traces generated by our own harness (licence-clean by construction);
5. soul/persona last, because it depends on a teacher that already answers well.

## What this plan does not fix

Volume without quality control is a bigger corpus that trains worse. Each source
needs its own filter — language ID, boilerplate, dedupe — and a sample read by a
human before it enters the mix. The builder's licence, secret and held-out gates
are necessary and not sufficient.
